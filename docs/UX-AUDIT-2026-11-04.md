# UX / Functionality Audit — 4 Nov 2026

## Scope and method
Reviewed the SPA entry/layout (`index.html`), route and feature modules under `src/js/`, CSS/design-system layers, Firebase data-flow/security documentation and rules, existing UX audit, and automated test suites. Installed the lockfile dependencies with `npm ci`; no application data or schema was changed. This is a repository-level audit; no authenticated production Firebase account or live deployment was available, so live network/API behavior and real-user task completion were not verified.

## Overall assessment
The application has a mature, well-documented static SPA architecture with Firebase Auth/Firestore/Storage and Cloud Functions for sensitive operations. It has extensive pure-logic coverage and a smoke test that exercises key end-to-end journeys against test doubles. The v34 flat design system, route access improvements, permissions controls, and mobile navigation are consistent with the documented product goals. All 186 unit tests and the full smoke suite passed in this environment. The main unresolved issues are operational/audit limits: browser geometry checks cannot run because the sandbox lacks `libnss3.so`, live Firebase behavior cannot be verified here, and npm reports high-severity vulnerabilities in development dependencies plus `xlsx` (no automatic fix available).

## Findings by priority

### Critical
- None identified from repository inspection or automated tests. This is not a claim that production has no critical issues: live service access and browser execution were unavailable.

### High
1. **Dependency audit — `puppeteer-core` dependency tree (development tooling):** `npm audit` reports high-severity findings in `puppeteer-core` and transitive packages (`@puppeteer/browsers`, `basic-ftp`, `chromium-bidi`, `extract-zip`, `get-uri`, `pac-proxy-agent`, `proxy-agent`, `zod`). NPM proposes `puppeteer-core@25.16.0`, a major update. Impact: primarily developers/CI executing browser tooling, not ordinary static-site runtime. Recommendation: assess upgrade compatibility with `@sparticuz/chromium` and test browser scripts before updating; no blind major bump was made.
2. **Dependency audit — `xlsx`:** NPM reports a high-severity issue for the direct `xlsx` dependency and no available fix. It is used by spreadsheet import/export paths. Impact depends on processing untrusted workbook content; treat uploaded/imported workbooks as untrusted. Recommendation: review the advisory and evaluate an actively maintained alternative or isolate/limit workbook parsing. No replacement was made because this changes a core import/export path and needs compatibility testing.

### Medium
1. **Browser responsive/visual verification unavailable in this sandbox:** mobile build succeeds, but mobile and desktop browser checks cannot launch Chromium because `libnss3.so` is absent. Thus actual rendered viewport geometry, touch-target measurements, and browser console/network behavior were not tested.
2. **Production Firebase integration unverified:** smoke tests run with stubs. Firestore Rules tests/emulator and production API calls were not run; actual permissions, indexes, storage uploads, Cloud Functions and network failure recovery need a configured Firebase environment.
3. **No live accessibility/SEO audit:** source includes accessible labels/navigation and a web manifest, but automated screen-reader/keyboard/contrast and deployed metadata checks were outside the available test execution.

### Low
1. **Existing product backlog in `docs/UX-FLAT-REDESIGN.md`:** several useful follow-ups remain recommendations, including compacting dashboard actions, grouping expense filters, consolidating export actions, and undo for destructive actions. They are incremental improvements, not regressions demonstrated by this audit.

## User journeys and architecture reviewed
- Trip list → trip dashboard → itinerary / expenses / settlement / members / documents / More and settings routes.
- Itinerary place creation/editing, schedule and cost linking; expense creation/editing/splitting and settlement calculations; trip settings, import/export, notifications and permissions.
- Hash router and feature-module separation; trip-scoped Firestore data, local preference caching, Firebase-backed persistence, security rules and Cloud Functions described in project docs.
- Responsive shell includes desktop navigation and mobile bottom navigation; styles are layered in tokens/components/refresh/flat CSS.

## Tests and results
- `npm ci`: passed; installed from lockfile. NPM reports 10 high vulnerabilities (0 production-only vulnerabilities under `npm audit --omit=dev`; full audit includes dev tooling and `xlsx`).
- `npm test`: passed — **186 passed, 0 failed**.
- `npm run test:smoke`: passed — full scripted SPA journey with test doubles; **no uncaught application errors**. Expected simulated permission/network/image failures were logged by the test harness.
- `npm run test:browser:build`: passed — 82 modules built.
- `npm run test:browser:mobile`: **blocked** before checks by missing system library `libnss3.so` required to start bundled Chromium.
- `npm run test:browser:desktop`: **blocked** for the same reason.
- `npm audit --omit=dev`: passed — 0 production-only vulnerabilities reported by npm.
- Live Firebase, Firestore emulator/rules, deployment network requests, and screen-reader checks: not run.

## Changes made during follow-up improvement work
- Added a shared primary-navigation registry (`src/js/navigation.js`) and made desktop navigation render from it, escaping visible labels and URL-encoding the trip identifier. The route handlers, auth flow, API contract and database schema were not changed.
- Replaced the theme foreground's simple luminance threshold with WCAG 2.x relative-luminance/contrast-ratio selection. Preset and custom primary foreground colors now select the better of white/black, and tests enforce at least 4.5:1 for all registered preset primary colors.
- Theme selection now exposes its selected state using `aria-pressed`; the custom-theme preview uses the contrast-selected ink and explicitly explains that theme preferences are saved only in this browser/device.
- Added `docs/FRONTEND-IMPROVEMENTS.md` with module boundaries, navigation/theme accessibility contracts and safe extension guidance.
- Authentication, API contracts and database schema remain unchanged.

## Recommended next steps
1. Upgrade and validate browser tooling in CI, and install Chromium system libraries so mobile/desktop checks can execute.
2. Review the `xlsx` advisory and choose a tested mitigation/replacement before accepting untrusted spreadsheet uploads broadly.
3. Run Firebase emulator rules tests and authenticated staging journeys, covering permission-denied, offline/retry, imports, uploads and destructive actions.
4. Perform keyboard/screen-reader and color-contrast checks on desktop and mobile; prioritize the expense filter/export workflow and destructive-action undo from the existing backlog.
