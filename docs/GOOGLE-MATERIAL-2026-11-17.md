## 3.6 รอบที่ 3 — ใบเสร็จรายคน + แผนที่หนี้ ออกแบบใหม่ (17 Nov 2026)

เจ้าของขอ: *“ใบเสร็จรายคนใหม่ทั้งหมด แยกส่วนที่ต้องรับ ต้องจ่าย และจ่ายสุทธิ
พร้อมจ่ายใครบ้างของรายบุคคลนั้น ใช้สีแยกให้ชัดเจนกว่านี้ กดดูแบบกระทัดรัดและ
รายละเอียดทั้งหมดได้ และแผนที่หนี้ที่ตัวเลขบนเส้นทับกัน/ไม่รู้ว่าเป็นของใคร
ออกแบบใหม่ทั้งหมด”*

### 3.6.1 ใบเสร็จรายคน — “การ์ดคำตอบ 4 ใบ”

เดิม: ยอดสุทธิเป็น hero เล็ก ๆ มุมขวา แล้วตามด้วยบล็อก รับ / หัก / คงเหลือ
ซึ่งปนกับรายการยาว ๆ reader ต้องไล่อ่านเอง

ใหม่: การ์ดคำตอบ 4 ใบที่ **เห็นตลอดทั้งสองโหมด** (กระทัดรัด/ละเอียด):

| การ์ด | สี | เนื้อหา |
|---|---|---|
| **ต้องรับ** | เขียว (green 900 `#0d652d` บน tint `#e6f4ea`) | เงินที่คนนี้จ่ายไปก่อน + จำนวนรายการ + แยกวิธีจ่าย |
| **ต้องจ่าย** | แดง (Material error `#b3261e` บน `#fce8e6`) | ส่วนที่ต้องรับผิดชอบ + จำนวนรายการ + จำนวนที่ถูกทักท้วง |
| **สุทธิ** | ฟ้า/เขียว/แดง (blue 700 `#1967d2` บน `#e8f0fe`) | ตัวเลขเดียวที่ต้องจำ + ทิศทาง (ได้คืน/ต้องจ่าย/เคลียร์) — **การ์ดนี้ขึ้นก่อนบนมือถือ** |
| **โอนให้ใคร** | ขอบซ้ายสีตามทิศทาง | ปุ่มรายชื่อ: `โอนให้ นุ่น −฿2,128.08` / `รับจาก …` กดแล้วเปิดค่าใช้จ่ายของคนนั้น |

- **แถบสีซ้าย 4px** ของแต่ละการ์ดทำให้แยกออกได้แม้พิมพ์ขาวดำ/เป็นภาพ PNG
- วัดคอนทราสต์บนพื้น tint จริง (ไม่ใช่บนขาว): เขียว **6.34**, แดง **5.55**, ฟ้า **4.68** — ผ่าน AA ทั้งหมด
- ยอดหัวการ์ดแสดง **บาทถ้วน** เมื่อเป็นจำนวนเต็ม และมีสตางค์เฉพาะการ์ดสุทธิ (ตัวเลขที่ต้องโอนจริง)
  ส่วนบล็อกรายละเอียดยังมีสตางค์ครบทุกบรรทัด
- รายการย่อย (รับ/หัก/คงเหลือ) อยู่ใน `.rcpt-details` — โหมด **กระทัดรัด** พับเฉพาะส่วนนี้
  การ์ดคำตอบทั้ง 4 ใบยังอยู่ครบ (ทดสอบใน smoke test)
- PNG/print: `export-flat` ประกาศสีใหม่ให้ตรงกับ tint ใหม่ เพื่อให้ภาพออกมาเหมือนจอ

### 3.6.2 แผนที่หนี้ — ยอดเงินอยู่บนเส้นของตัวเองเสมอ

สาเหตุเดิม: ป้ายยอดถูกวางด้วยอัลกอริทึม “หาที่ย่างได้รอบเส้น” ซึ่งเมื่อ Kunze
พื้นที่ไม่พอจะไปวางทับเส้นอื่นหรือถูกผลักลงไปเป็นแถวท้ายภาพ ทำให้ไม่รู้ว่ายอดไหนของใคร

ใหม่ (`src/js/utils/debtMap.js → placeDebtMapPill`, unit-tested 3 เคส):

1. ทุกเส้นโค้งเข้าหาศูนย์กลาง; ยอดเงินเป็น **pill** ที่มี **เลขกำกับ** (`1`, `2`, `3` …)
   และ **walk อยู่บนเส้นของตัวเองเท่านั้น** (sample t = 0.5 → 0.12/0.88)
2. ทุก pill ถูกกันไม่ให้ทับ **โหนดคน** หรือ **pill อื่น** (ระยะห่าง 5px) — ถ้าไม่มีที่จริง ๆ
   ฟังก์ชันคืน `null` และ **ยอดนั้นไปอยู่ในรายการเลขด้านบน** พร้อมข้อความ
   “ยอดนี้ไม่ได้เขียนบนเส้น (พื้นที่ไม่พอ) — ดูเลข N ในรายการ” (แถวนั้นมีเส้นประที่ขอบซ้าย)
3. รายการโอนเป็น **แหล่งความจริง**: เลขในวงกลมบนเส้น = เลขในรายการ, ชื่อผู้โอน/ผู้รับ
   กดได้ทั้งคู่, ยอดเงินเป็น Google Sans Code ชิดขวา, มีปุ่ม “จ่ายแล้ว” ต่อแถว
4. แผนภาพยังอยู่ใน `<details>` (เริ่มปิด) เหมือนเดิม — ใช้ยืนยันด้วยตา ไม่ใช่ต้องอ่านเพื่อทำงาน

ตรวจด้วยข้อมูลจริงจาก preview: 3 เส้น → 3 pill, ทับกัน 0, ทับโหนด 0 (สคริปต์วัดใน §6)

## 5. จุดที่ควรตรวจด้วยตา (screenshots ทำไม่ได้ใน environment นี้)

เครื่องใน sandbox ไม่มีเบราว์เซอร์ headless (`libnss3` หาย, ติดตั้งไม่ได้) จึงตรวจด้วย
โค้ด/เทสต์เท่านั้น หน้าจอที่ควรเปิดดูเอง:

1. **แถบบน desktop** — โลโก้วงกลม 40px, แท็บกลม, แท็บ active เป็นพิลน้ำเงิน, ความสูงรวม 113px
   (แถวแบรนด์ 64 + แถวแท็บ 48) และหน้าที่มี `.page-head` ไม่ชนแถบ
2. **แถบล่างมือถือ** — dock พิลสูง 48px, ไอเท็ม active เป็นพิล tint, ไม่มีขีด `::before`
3. **แดชบอร์ด** — การ์ดขาวเงา 1dp, KPI 3 ช่องในแถวเดียว, การ์ด widget มีแถบสี 3px หน้าหัวข้อ
4. **ค่าใช้จ่าย/เคลียร์บิล** — ชิปตัวกรองเป็นพิล, ปุ่มเลือกวิธีจ่าย active เป็น tint 10% + ขอบน้ำเงิน,
   ใบเสร็จกระดาษขาว + ตัวเลข Google Sans Code
5. **โหมดมืด** — ปุ่มหลัก/แท็บ active/FAB ต้องเป็นน้ำเงินอ่อน `#63a0ef` กับ **หมึกเข้ม**
   (ถ้าเห็นตัวอักษรขาวบนน้ำเงินอ่อน = ถอยหลัง ให้กลับไปดู §3)
6. **ฟอนต์ไทย** — Google Sans มี subset ไทยจริง; ตัวเลขในปฏิทิน/ใบเสร็จควรเป็น tabular
   และ Google Sans Code ใช้เฉพาะอักษรละติน/ตัวเลข (ไม่มีไทย — ตั้งใจ)

พรีวิวแบบเต็มหน้า (CSS + ฟอนต์ + ไอคอนครบ): `tools/preview/out/<route>.full.html`
(`dashboard`, `trips`, `expenses`, `settlement`, `settings`) และ `*.full-dark.html`
