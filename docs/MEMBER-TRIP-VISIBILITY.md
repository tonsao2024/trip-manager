# สมาชิกอยู่ในทริป แต่เข้าสู่ระบบแล้วไม่เห็นทริป (memberUids drift)

## อาการ

- ผู้ดูแลทริป (trip admin) เปิดหน้า “สมาชิก” แล้วเห็นสมาชิกครบทุกคน
- แต่สมาชิกแต่ละคนเข้าสู่ระบบ (Google/อีเมล) สำเร็จ แล้วหน้า “ทริปของฉัน” ว่างเปล่า — ไม่มีทริปนี้อยู่เลย

## สาเหตุ

ข้อมูลสมาชิกถูกเก็บไว้ **2 ที่** ซึ่งต้องตรงกัน:

| ที่เก็บ | ใครอ่าน | ใช้ทำอะไร |
|---|---|---|
| `trips/{tripId}/members/{memberId}` (เอกสารสมาชิก) | หน้าสมาชิกของแอดมิน | รายชื่อที่แอดมินเห็น |
| `trips/{tripId}.memberUids` (array ของ uid บนเอกสารทริป) | รายการทริปของสมาชิก + Firestore rules ข้อ `list` | ค้นว่า “ฉันอยู่ทริปไหนบ้าง” (`where('memberUids', 'array-contains', uid)`) |

Firestore ตอบคำถาม “ทริปไหนมีเอกสาร `members/{uidของฉัน}` บ้าง” จากเอกสารทริปอย่างเดียวไม่ได้
รายการทริปจึงพึ่ง `memberUids` เป็นหลัก เมื่อใดที่สองที่นี้ **เพี้ยน (drift)** จากกัน —
เอกสารสมาชิกมีอยู่ แต่ uid ของบัญชีที่ล็อกอินไม่เคยเข้าไปอยู่ใน `memberUids` — ผลคือ:

- แอดมิน (อ่านเอกสารสมาชิก) เห็นทุกคนตามปกติ → ดูเหมือน “ระบบปกติ”
- สมาชิก (ค้นจาก `memberUids`) ไม่เจอทริปเลย → ดูเหมือน “ทริปหาย”

กรณีที่ทำให้เพี้ยนได้ เช่น ทริปเก่าที่สร้างก่อนมี `memberUids`, การเขียน array ไม่สำเร็จแต่ถูกกลืนเป็น
`console.warn`, **ทริปที่ถูกทำสำเนา** (เดิมคัดลอกเฉพาะเอกสารสมาชิก ไม่ได้คัดลอก `memberUids`),
และสมาชิกแบบพิมพ์ชื่อ/PIN (`mb…`) ที่ภายหลังเปลี่ยนมาล็อกอินด้วยบัญชี Google/อีเมล
ซึ่งเป็น uid คนละชุดกันโดยไม่มีตัวเชื่อม

## วิธีแก้ที่ทำในโค้ด

1. **ค้นหาทริปจากเอกสารสมาชิกโดยตรง** (`fetchTripsFromServer` ใน `src/js/trips/index.js`):
   นอกจาก query `memberUids` และ `createdBy` (เดิมเจอแหล่งใดแหล่งหนึ่งแล้วหยุด — ตอนนี้ **รวมทุกแหล่ง**
   ไม่ตัดกันเอง) จะค้นเอกสารสมาชิกของบัญชีนี้ทั่วทุกทริป (collection group `members` โดย `uid`/`authUid`)
   แล้วอ่านทริปนั้น ๆ สมาชิกที่มีเอกสารอยู่จริง (และไม่ถูกปิดใช้งาน) จะเห็นทริปทันที แม้ array จะยังเพี้ยน
2. **ซ่อมตัวเองอัตโนมัติ**: ทริปที่เจอจากข้อ 1 จะถูกเติม uid ของตัวเองกลับเข้า `memberUids`
   (กฎอนุญาตเฉพาะ “เพิ่ม uid ของตัวเอง 1 รายการ” เท่านั้น — เพิ่มให้คนอื่น/แก้ฟิลด์อื่นไม่ได้)
3. **แอดมินซ่อมทั้งทริปอัตโนมัติ**: เปิดหน้า “สมาชิก” ในฐานะแอดมิน/ผู้จัดการสมาชิก
   ระบบเติม uid ที่ขาดของสมาชิกที่ยังใช้งานอยู่ทุกคนเข้า `memberUids` ให้ในครั้งเดียว
   (`reconcileTripMemberUids`)
4. **ทริปที่ทำสำเนา**: `duplicateTrip` เติม `memberUids` ของทริปใหม่จากเอกสารสมาชิกที่คัดลอกมาด้วย
5. ตรรกะคำนวณ uid อยู่ใน `src/js/utils/memberUids.js` (unit test: `tests/unit/member-uids.test.js`)

## สิ่งที่ต้อง deploy เพิ่ม (ครั้งเดียว)

โค้ดฝั่งเว็บ (GitHub Pages) อย่างเดียวไม่พอ ต้องเผยแพร่กฎและดัชนีชุดใหม่ด้วย:

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

- `firestore.rules`: เพิ่มกฎ `/{path=**}/members/{memberId}` ให้บัญชีอ่านเอกสารสมาชิกของตัวเอง
  (ค้นหาทริป) และ `memberMayRestoreOwnListing` ให้สมาชิกเติม uid ตัวเองกลับเข้า `memberUids`
- `firestore.indexes.json`: เพิ่ม field override ให้ query collection-group บน `members.uid` / `members.authUid` ใช้ได้

ถ้ายังไม่ deploy กฎ: เว็บยังใช้ query `memberUids` เดิมได้ตามปกติ (การค้นหาแบบใหม่ล้มเหลวแบบเงียบ ๆ
และไม่ซ่อนทริปที่หาเจอแล้ว) แต่สมาชิกที่ข้อมูลเพี้ยนอยู่จะยังไม่เห็นทริป จนกว่าจะ deploy กฎ
และให้แอดมินเปิดหน้า “สมาชิก” ของทริปนั้น 1 ครั้ง (หรือสมาชิกเข้าเว็บอีกครั้งหลัง deploy)

## ตรวจว่าหายจริง

1. ให้สมาชิกที่เคยไม่เห็นทริปเข้าสู่ระบบใหม่ → ทริปต้องปรากฏใน “ทริปของฉัน”
2. ถ้ายังไม่ปรากฏ ให้แอดมินเปิดทริป → หน้า “สมาชิก” (ระบบซ่อม `memberUids` ให้และแจ้งเตือน)
   แล้วให้สมาชิกรีเฟรช/เข้าใหม่
3. สมาชิกที่ล็อกอินด้วยชื่อผู้ใช้/PIN เดิม และสมาชิกที่แอดมิน “เพิ่มด้วยอีเมล” ไม่ได้รับผลกระทบ
   (กรณีหลังต้องตรวจว่าไม่มีรายชื่อซ้ำ 2 แถว — แถวบัญชี `account` คือแถวที่ใช้ล็อกอิน)

## ถ้ายังมี “รออนุมัติ” ค้าง หรือแอดมินไม่เห็นคำขอ

การซ่อม `memberUids` ด้านบนแก้แค่เรื่อง **รายการทริปหาย** ยังไม่แตะคำขอเข้าร่วมที่เขียนค้าง
(เขียน 2 ที่: คิว `trips/{id}/joinRequests/{uid}` + mirror ส่วนตัว `users/{uid}/joinRequests/{tripId}`)
หรือเอกสารสมาชิกที่ติด `status: 'pending'`. ใช้ปุ่ม **“กวาดสถานะค้าง”** ในหน้าสมาชิก และ
**“ซิงก์คำขอค้าง”** ในหน้าทริปของฉัน — ดู [docs/MEMBERSHIP-REPAIR-2026-11-19.md](MEMBERSHIP-REPAIR-2026-11-19.md).

## รอบ 2 (19 Nov 2026) — “แอดมินอนุมัติแล้ว แต่สมาชิกยังขึ้น ตรวจสอบทริปที่เคยเข้าร่วมไม่ครบ”

อาการที่รายงาน: สมาชิกใหม่ใส่รหัสเชิญ → แอดมินกดอนุมัติ → หน้าทริปของสมาชิกยังขึ้น
**“ตรวจสอบทริปที่เคยเข้าร่วมไม่ครบ — ตรวจการเชื่อมต่อและการ deploy Firestore Rules/Indexes แล้วลองใหม่”**

ข้อความนี้ถูก throw จาก `fetchTripsFromServer()` เฉพาะเมื่อ **ไม่พบทริปเลยสักใบ และมีอย่างน้อย 1
แหล่งข้อมูลที่อ่านไม่สำเร็จ** ดังนั้นสาเหตุจริงมีได้ 2 อย่างซ้อนกัน:

| ชั้น | ปัญหา | ผล |
|---|---|---|
| 1. การอนุมัติ | โค้ดเดิมอ่านทริปด้วย `getDoc()` (**อาจเป็นแคช**) แล้วข้ามการเขียน `memberUids` เมื่อ “เห็นว่า uid อยู่ในลิสต์แล้ว” | เอกสารสมาชิกถูกสร้าง แต่ `memberUids` ไม่ถูกเขียน → แอดมินเห็นสมาชิก แต่ `where('memberUids','array-contains',uid)` ไม่เจอ |
| 2. การค้นหา | ถ้า `memberUids` ขาด **และ** collection-group index (`members.uid`) ยังไม่ถูก deploy | ทั้ง 3 แหล่งเดิม (memberUids / createdBy / member docs) ว่างพร้อมกัน → ขึ้น error แทนที่จะเห็นทริป |

### สิ่งที่แก้ (ฝั่งเว็บเท่านั้น — **ไม่ต้อง deploy กฎใหม่**)

1. **อนุมัติเขียน `memberUids` เสมอ** (`src/js/members/join.js`)
   - อ่านทริปด้วย `getDocFromServer()` (ไม่ใช้แคชในการตัดสินสิทธิ์)
   - เขียน `arrayUnion(uid)` ทุกครั้งใน writeBatch เดียวกับเอกสารสมาชิก — `arrayUnion`
     ไม่เพิ่มซ้ำ การเขียนทุกครั้งจึงปลอดภัย และไม่มีทาง “ลืมเขียน” อีก
   - หลัง commit **ตรวจซ้ำจากเซิร์ฟเวอร์** (`tripListsMember`) แล้วคืนค่า `listed`; ถ้า `false`
     หน้า สมาชิก ขึ้นคำเตือนแทนคำว่า “อนุมัติแล้ว” และรายการสมาชิกที่โหลดต่อจะ `reconcileTripMemberUids` ให้ทันที

2. **แหล่งค้นหาทริปที่ 4: ทริปที่บัญชีนี้ “ขอเข้าร่วม” ไว้** (`src/js/trips/index.js` + `listJoinTargets()`)
   - ใช้เฉพาะเมื่อแหล่ง 1–3 ว่างทั้งหมด (ไม่กระทบเส้นทางปกติ/ไม่เพิ่ม read ในหน้าปกติ)
   - ที่มาของ tripId: mirror ส่วนตัว `users/{uid}/joinRequests/{tripId}` (กฎอนุญาตเฉพาะเจ้าของ
     แอดมินลบไม่ได้ จึงยังอยู่หลังอนุมัติ) + รายการที่จำไว้บนเครื่อง (`localStorage: fuji_join_targets`,
     จำกัด 20 รายการ, ลบเมื่อเห็นทริปแล้ว/ยกเลิกคำขอ)
   - อ่านทริปเป็นรายใบด้วย `getDocFromServer()` — กฎ `isTripMember` เปิดให้อ่าน **เฉพาะเมื่อเป็นสมาชิกจริง**
     ดังนั้นคำขอที่ยัง pending/ถูกปฏิเสธจะไม่เห็นทริป (และไม่ทำให้เกิด error)
   - เจอทริป → เติม `memberUids` ของตัวเองกลับให้อัตโนมัติ (`memberMayRestoreOwnListing`)

3. **ข้อความ error ที่บอกสาเหตุจริง + ปุ่ม “ตรวจสิทธิ์อีกครั้ง”** (`src/js/app.js`)
   - error แนบ `details` (code/message ของแต่ละแหล่ง) และ `requiresDeploy`
   - หน้า ทริปของฉัน แสดง 3 ขั้นตอนที่ทำได้จริง (ตรวจสิทธิ์อีกครั้ง / deploy กฎ+ดัชนี / ตรวจบัญชีที่ล็อกอิน)
     พร้อมรายละเอียดทางเทคนิคแบบพับได้ และปุ่ม retry จะล้างแคชก่อนอ่านใหม่

### สิ่งที่ยังต้อง deploy (ถ้าต้องการให้การค้นหา “ตรง” 100%)

โค้ดชุดนี้ทำงานได้กับกฎที่ deploy อยู่แล้ว (ใช้ `isTripMember` + `memberMayRestoreOwnListing` เดิม)
แต่ถ้าต้องการให้แหล่งที่ 3 (ค้นจากเอกสารสมาชิก) ใช้ได้ด้วย ต้องมี collection-group index:

```bash
firebase deploy --only firestore:indexes   # members.uid / members.authUid (COLLECTION_GROUP)
```

ถ้ายังไม่มี index ระบบจะยังพาสมาชิกที่อนุมัติแล้วเข้าได้ทางแหล่งที่ 4 และขึ้นแถบ “โหลดได้บางทริป”
(ไม่ใช่หน้า error) พร้อมบอกว่าแหล่งไหนอ่านไม่ได้

### ตรวจว่าแก้จริง

1. แอดมินกดอนุมัติ → toast ต้องเป็น “อนุมัติ … แล้ว” (ไม่ใช่คำเตือน `memberUids`)
2. ใน Firestore: `trips/{tripId}.memberUids` ต้องมี uid ของสมาชิกทันทีหลังอนุมัติ
3. สมาชิกเปิด/รีเฟรชหน้า ทริปของฉัน → เห็นทริป (แม้ยังไม่ deploy index)
4. ถ้ายังไม่เห็น → กด **ตรวจสิทธิ์อีกครั้ง** แล้วดู “รายละเอียดทางเทคนิค” ว่าเป็น
   `permission-denied` (กฎ) หรือ `failed-precondition` (ขาด index)
